# 게임 서버 (FUNC-005)

서버 범위는 FUNC-005-01~13, 15~16과 FUNC-006-01이다. 방 생성·참가·관전석·채팅에 게임 엔진을 연결했다. 게임 화면 미리보기의 서버 이벤트 연결과 Howler 효과음(005-14)은 프론트엔드 후속 작업이다.

## 규칙

- 과일 4종 × 14장 = 56장. 각 과일은 1개 카드 5장, 2개 3장, 3개 3장, 4개 2장, 5개 1장이다. 서버의 암호학적 난수로 Fisher–Yates 셔플한다.
- 방의 `PLAYER` 2~6명에게 동일 장수로 나누고 나머지는 보관 스택에 넣는다. 원래 관전자는 덱·경기 결과를 받지 않는다. 방 전체 인원은 기존 참가자 6명 + 관전석 10명 규칙을 따른다.
- 첫 차례는 참가석 입장 순서의 첫 회원이다. 탈락·이탈자는 턴에서 제외한다. 손패가 0장이 되는 즉시 탈락하며 그 사람의 테이블 카드도 보관 스택으로 옮긴다.
- 공개 테이블에서 같은 과일 합이 정확히 5이면 종 성공이다. 선착순 한 명이 테이블 전체와 보관 스택을 자기 덱 아래에 넣고 다음 라운드를 시작한다.
- **2026-11-04 첨부 이미지 기준 오발**: 오발자의 카드 1장과 테이블 전체를 보관 스택으로 옮긴다. 다음 정상 종 승자가 가져간다. 오발 후 기존 차례를 이어가며, 그 차례의 사람이 탈락했으면 다음 생존자로 넘긴다.
- 종 판정 후 턴 제한 시간은 새로 10초다. 10초 안에 직접 내지 않으면 서버가 대신 낸다. 한 회원이 세 번 연속 자동 내기하면 이탈 처리한다. 직접 내면 연속 횟수는 0으로 돌아간다.
- 한 명만 남으면 종료한다. 최후 생존자, 탈락·이탈 순서의 역순으로 순위를 만든다. 이탈자는 순위를 유지하면서 0점이다. 나머지 회원은 이탈자를 제외한 보상 순위로 기존 지급식을 적용한다.
- 탈락·연결 유예 만료·자동 내기 이탈은 방에 관전자로 남는다. 직접 방을 나가면 소속도 제거한다. 관전자는 같은 전체 상태와 채팅을 받지만 카드 내기·종은 `SPECTATOR_FORBIDDEN`이다.
- 종료 후 남아 있는 원래 참가자는 참가석으로, 원래 관전자는 관전석으로 돌아간다. 게임 중 나간 방장의 권한은 종료 시 남은 첫 회원에게 넘어간다.

## 계층과 동시성

`GameGateway → GameService → Game / GamePlayer / Table / Deck` 순으로 연결된다. 도메인에는 NestJS·DB·Redis·Socket.io 의존성이 없고, 모든 규칙 변경이 동기로 끝난다. 서비스는 `RoomQueue`에 요청을 접수한 다음 인증·Redis·DB를 기다린다. 먼저 접수된 종 요청이 느린 인증 때문에 뒤 요청에 추월당하지 않는다. 자동 턴, 연결 유예 만료, 게임 중 나가기와 실제 방 소속 제거도 같은 큐에서 처리한다.

게임 원본은 서버 1대의 메모리 객체이고 Redis에는 내부 상태를 미러링한다. 자동 턴은 서버의 절대 마감 시각을 사용한다. 다른 탭이 연결돼 있으면 끊김으로 세지 않는다. 마지막 탭이 끊겼을 때 게임 중 5초, 대기실 60초 유예를 적용한다. 재접속 시 같은 게임의 전체 공개 스냅샷을 보낸다. 게임 중 턴 타이머는 연결 유예 중에도 계속 진행한다.

현재 방 저장소도 메모리이므로 **프로세스 재시작 후 게임·방의 자동 복구는 지원하지 않는다**. Redis 미러를 새 서버의 권위 있는 상태로 읽어 복원하지 않으며, 여러 게임 서버 운영을 지원하는 분산 엔진도 아니다.

## 소켓 계약

기존 같은 출처 Socket.io 연결에서 `auth.token`에 Access JWT를 넣는다. 게임 이벤트는 매 요청에도 토큰·계정 버전을 검증한다. 발신자 ID·카드·클라이언트 시각은 입력으로 받지 않는다.

| 방향 | 이벤트 | 페이로드 |
|---|---|---|
| C→S | `room:start` | `{}` — 방장만, 참가자 최소 2명 |
| C→S | `card:play` | `{ gameId, turnId }` |
| C→S | `bell:ring` | `{ gameId, turnSeq }` |
| C→S | `game:sync` | `{}` — 이 소켓에 현재 전체 상태 재전송 |
| C→S | `game:return` | `{}` — 종료·정산 확인 후 이 소켓에 `game:state: null` |
| S→C | `game:state` | `GameSnapshot \| null` |
| S→C | `game:action` | 카드 내기·종 판정·이탈·연결 변경 `GameActionEvent` (gameId·revision 포함) |

Ack는 `{ ok: true }`, 지난 중복 요청이면 `{ ok: true, ignored: true }`, 실패면 `{ ok: false, code }`다. 연결 끊김으로 Ack가 오지 않으면 클라이언트는 시간 초과로 안내하고 `game:sync` 또는 재접속 후 상태를 확인해야 한다.

스냅샷의 `turnId`는 새 차례(카드 내기·종 판정)에 변경된다. 카드 내기에는 마지막 스냅샷의 `turnId`를 그대로 보낸다. `turnSeq`는 카드가 공개될 때마다 증가한다. 종에는 현재 `turnSeq`를 보낸다. 같은 `turnSeq`의 종은 판정이 한 번 끝나면 다음 카드가 나오기 전까지 무시한다. `gameId`는 이전 판의 지연 요청이 새 판에 영향을 주지 않도록 반드시 함께 보낸다.

스냅샷에는 보유 카드 **개수**, 맨 위 공개 카드, 테이블 개수, 과일 합계, 상태, 연결 상태, 자동 내기 횟수, 턴·마감 시각과 최종 결과가 있다. 숨긴 손패의 과일·순서는 보내지 않는다. `revision`은 공개 상태 변경 순서이며 클라이언트가 오래된 상태를 걸러낼 수 있다. `settled`는 결과·포인트 DB 반영 완료 여부다.

## Redis 미러와 정산

| Key | 형식 | 내용 / 수명 |
|---|---|---|
| `game:{id}` | Hash | roomCode, status, round, turnUserId, turnSeq, turnId, lastPlayAt, startedAt |
| `game:{id}:order` | List | 살아 있는 참가자 userId, 자리 순서 |
| `game:{id}:hand:{userId}` | List | 숨긴 덱, 왼쪽이 맨 위. `S3` 같은 과일 이니셜+개수 |
| `game:{id}:table:{userId}` | List | 테이블 전체 카드, 왼쪽이 맨 위 |
| `game:{id}:pile` | List | 종 아래 보관 카드 |
| `game:{id}:out` | List | 탈락·이탈한 userId, 발생 순서 |
| `game:{id}:stat:{userId}` | Hash | bellSuccess, bellFail, reactionSum(ms) |
| `game:{id}:bell:{turnSeq}` | String | 최초 종 userId, SET NX EX 10. 정리 인덱스 기록까지 Lua로 처리 |
| `game:{id}:keys` | Set | 같은 게임의 모든 Redis 키, 정산 후 누락 없이 삭제하기 위한 인덱스 |
| `settled:{id}` | String | DB 반영 완료 표식, 1일 |

게임 상태 키는 첨부 명세에 따라 TTL 없이 유지하고 종료 정산 성공 후 삭제한다. 미러 전체는 Redis MULTI로 갱신한다. 원본 도메인과 보관 덱은 클라이언트가 수정할 수 없다.

최종 결과는 기존 PostgreSQL `Game`·`GameResult`·포인트 트랜잭션으로 저장한다. 중복 지급의 최종 방어는 DB의 게임 ID 유니크 제약이다. DB가 실패하면 결과를 메모리와 Redis에 남기고 1초 뒤 같은 큐에서 재시도한다. `settled: false` 동안 다음 판 시작을 거부한다. 마지막 사람이 방을 나가도 정산 재시도는 남는다. Redis 정리에 실패해도 다음 판이 그 정리 작업을 덮어쓰지 않게 한다. Redis 미러만 실패한 경우 이미 확정한 카드를 되돌리지 않고 같은 상태를 다시 저장한다.

## 검사

`pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 실행한다. 실제 통합 테스트는 별도의 빈 테스트 DB를 만든 뒤 기존 마이그레이션을 적용해 실행한다. 기존 개발 DB를 초기화할 필요는 없다.

```sh
POSTGRES_DB=nlmlio_game_test pnpm db:deploy
POSTGRES_DB=nlmlio_game_test pnpm test:e2e
```

도메인 테스트는 분배·과일 합·카드 보존·벌칙·탈락·순위·타이머를 검증한다. 서비스 테스트는 가짜 시간으로 자동 내기·연결 유예·재시도·접수 순서를 검증한다. 통합 테스트는 실제 소켓·Redis·PostgreSQL을 이용해 방 시작부터 카드·동시 종·재접속·이탈·정산·Redis 정리까지 확인한다. 통합 테스트의 셔플 팩토리만 결정적인 덱으로 교체하며 게임 규칙·저장소·네트워크는 실제 구현이다.
