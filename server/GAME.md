# 게임 서버 (FUNC-005)

서버 범위는 FUNC-005-01~13, 15~16이다(포인트 FUNC-006은 제외). 방 생성·참가·관전석·채팅에 게임 엔진을 연결했다. 클라이언트 게임 화면(`client/src/pages/game/GamePage.tsx`)이 아래 소켓 계약으로 붙어 있고, Howler 효과음(005-14)은 클라이언트가 낸다. 턴 시간(`TURN_TIME_MS`)과 게임 중 재접속 유예(`GAME_RECONNECT_GRACE_MS`)는 `shared/src/game-events.ts`에서 양쪽이 같이 쓴다.

## 규칙

- 과일 4종 × 14장 = 56장. 각 과일은 1개 카드 5장, 2개 3장, 3개 3장, 4개 2장, 5개 1장이다. 서버의 암호학적 난수로 Fisher–Yates 셔플한다.
- 방의 `PLAYER` 2~6명에게 동일 장수로 나누고 나머지는 보관 스택에 넣는다. 원래 관전자는 덱·경기 결과를 받지 않는다. 방 전체 인원은 기존 참가자 6명 + 관전석 10명 규칙을 따른다.
- 첫 차례는 참가석 입장 순서의 첫 회원이다. 탈락·이탈자는 턴에서 제외한다. 마지막 카드를 내면 종 판정까지 살아 있고 차례에서만 빠진다. 다음 종 판정 뒤에도 덱이 0장이면 탈락한다.
- 공개 테이블에서 같은 과일 합이 정확히 5이면 종 성공이다. 선착순 한 명이 테이블 전체와 보관 스택을 자기 덱 아래에 넣고 다음 라운드를 시작한다.
- **2026-11-19 수정 오발**: 오발자는 자신을 제외한 각 생존 플레이어에게 보유 카드를 1장씩 덱 아래로 준다. 탈락·이탈·관전자는 받지 않는다. 부족하면 참가석 순서로 가진 만큼만 주고, 보유 카드가 0장이면 더 주지 않는다. 모든 플레이어 앞에 쌓인 테이블 카드는 맨 위뿐 아니라 아래까지 전부 종 아래 보관 스택으로 모은다. 기존 보관 카드는 유지하며 다음 정상 종 승자가 가져간다. 오발 후 기존 차례를 이어가되 탈락한 사람은 차례에서 제외한다.
- 종 판정 결과를 `ROUND_RESULT_MS`(1.8초) 동안 표시하고, 서버도 이 동안 카드 요청을 무시한다. 스냅샷의 `roundResumeAt` 이후부터 온전한 새 차례 10초를 준다. 10초 안에 직접 내지 않으면 서버가 대신 낸다. 한 회원이 세 번 연속 자동 내기하면 이탈 처리한다. 직접 내면 연속 횟수는 0으로 돌아간다.
- 한 명만 남으면 종료한다. 최후 생존자, 탈락·이탈 순서의 역순으로 순위를 만든다. 이탈자는 패배로 기록한다. 모두 덱이 0장이면 마지막 카드 이후 10초 동안 종 기회를 주고, 응답이 없으면 마지막으로 카드를 낸 사람이 승리한다. 포인트 기능은 없다.
- 탈락·연결 유예 만료·자동 내기 이탈은 방에 관전자로 남는다. 직접 방을 나가면 소속도 제거한다. 관전자는 같은 전체 상태와 채팅을 받지만 카드 내기·종은 `SPECTATOR_FORBIDDEN`이다.
- 진행 중에도 방 코드로 관전 입장이 가능하다. 참가석이 비어 있어도 관전자로 배정하며 새 관전 입장 10석·전체 16명 제한을 지킨다. 탈락한 원래 참가자는 새 관전 정원을 소모하지 않는다. `RoomGameLifecycle.joined`가 입장자의 모든 소켓에 현재 공개 스냅샷을 보내며 덱·차례·결과에는 추가하지 않는다. 채팅·이모티콘은 가능하고 카드·종·게임 중 자리 이동은 거부한다.
- 종료 후 남아 있는 원래 참가자는 참가석으로, 원래 관전자와 도중 입장 관전자는 관전석으로 돌아간다. 게임 중 나간 방장의 권한은 종료 시 남은 첫 회원에게 넘어간다.

## 계층과 동시성

`GameGateway → GameService → Game / GamePlayer / Table / Deck` 순으로 연결된다. 도메인에는 NestJS·DB·Redis·Socket.io 의존성이 없고, 모든 규칙 변경이 동기로 끝난다. 서비스는 `RoomQueue`에 요청을 접수한 다음 인증·Redis·DB를 기다린다. 먼저 접수된 종 요청이 느린 인증 때문에 뒤 요청에 추월당하지 않는다. 자동 턴, 연결 유예 만료, 게임 중 나가기와 실제 방 소속 제거도 같은 큐에서 처리한다.

게임 원본은 서버 1대의 메모리 객체이고 Redis에는 내부 상태를 미러링한다. 자동 턴은 서버의 절대 마감 시각을 사용한다. 다른 탭이 연결돼 있으면 끊김으로 세지 않는다. 마지막 탭이 끊겼을 때 활성 플레이어는 게임 중 5초 이탈 유예를 적용한다. 관전자(도중 입장·탈락 포함)는 게임 진행 여부와 무관하게 60초 안에 돌아오면 유지하고, 지나면 방에서 정리한다. 연결이 없는 채 HTTP로 관전 입장한 경우에도 같은 정리 타이머를 건다. 재접속 시 같은 게임의 전체 공개 스냅샷을 보낸다. 게임 중 턴 타이머는 연결 유예 중에도 계속 진행한다.

현재 방 저장소도 메모리이므로 **프로세스 재시작 후 게임·방의 자동 복구는 지원하지 않는다**. Redis 미러를 새 서버의 권위 있는 상태로 읽어 복원하지 않으며, 여러 게임 서버 운영을 지원하는 분산 엔진도 아니다.

## 소켓 계약

기존 같은 출처 Socket.io 연결에서 `auth.token`에 Access JWT를 넣는다. 방·게임·채팅 이벤트는 매 요청에도 현재 소켓 토큰·계정 버전을 검증한다. 클라이언트는 만료 30초 전에 Refresh를 회전하고 `auth:refresh`로 기존 연결의 인증 정보만 교체한다. 토큰이 만료된 채 메시지를 받으려 하면 서버는 전달을 막고 `auth:required`를 보낸다. 클라이언트는 인증 갱신 후 채팅 채널을 재확인한다. 새 토큰의 회원 ID가 원래 소켓과 다르면 교체를 거부한다. 발신자 ID·카드·클라이언트 시각은 입력으로 받지 않는다.

| 방향 | 이벤트 | 페이로드 |
|---|---|---|
| C→S | `auth:refresh` | `{ token }` — 동일 회원의 유효한 Access 토큰으로 기존 연결 갱신 |
| S→C | `auth:required` | `{ code: TOKEN_EXPIRED }` — 채팅 수신 인증 갱신 요청 |
| C→S | `room:start` | `{}` — 방장만, 참가자 최소 2명 |
| C→S | `card:play` | `{ gameId, turnId }` |
| C→S | `bell:ring` | `{ gameId, turnSeq }` |
| C→S | `game:sync` | `{}` — 이 소켓에 현재 전체 상태 재전송 |
| C→S | `game:return` | `{}` — 종료·정산 확인 후 이 소켓에 `game:state: null` |
| S→C | `game:state` | `GameStateEvent \| null` — 스냅샷 + 보낸 순간의 서버 시각 `serverTime`(클라이언트 시계 차이 계산용) |
| S→C | `game:action` | 카드 내기·종 판정·이탈·연결 변경 `GameActionEvent` (gameId·revision 포함) |

Ack는 `{ ok: true }`, 지난 중복 요청이면 `{ ok: true, ignored: true }`, 실패면 `{ ok: false, code }`다. 연결 끊김으로 Ack가 오지 않으면 클라이언트는 시간 초과로 안내하고 `game:sync` 또는 재접속 후 상태를 확인해야 한다.

스냅샷의 `turnId`는 새 차례(카드 내기·종 판정)에 변경된다. 카드 내기에는 마지막 스냅샷의 `turnId`를 그대로 보낸다. `turnSeq`는 카드가 공개될 때마다 증가한다. 종에는 현재 `turnSeq`를 보낸다. 같은 `turnSeq`의 종은 판정이 한 번 끝나면 다음 카드가 나오기 전까지 무시한다. `gameId`는 이전 판의 지연 요청이 새 판에 영향을 주지 않도록 반드시 함께 보낸다.

스냅샷에는 보유 카드 **개수**, 맨 위 공개 카드, 테이블 개수, 과일 합계, 상태, 연결 상태, 자동 내기 횟수, 턴·마감 시각·판정 후 재개 시각(`roundResumeAt`)과 최종 결과가 있다. 숨긴 손패의 과일·순서는 보내지 않는다. `revision`은 공개 상태 변경 순서이며 클라이언트가 오래된 상태를 걸러낼 수 있다. `settled`는 결과 DB 반영 완료 여부다.

## Redis 미러와 정산

| Key | 형식 | 내용 / 수명 |
|---|---|---|
| `game:{id}` | Hash | roomCode, status, round, turnUserId, turnSeq, turnId, lastPlayAt, roundResumeAt, startedAt |
| `game:{id}:order` | List | 살아 있는 참가자 userId, 자리 순서 |
| `game:{id}:hand:{userId}` | List | 숨긴 덱, 왼쪽이 맨 위. `S3` 같은 과일 이니셜+개수 |
| `game:{id}:table:{userId}` | List | 테이블 전체 카드, 왼쪽이 맨 위 |
| `game:{id}:pile` | List | 종 아래 보관 카드 |
| `game:{id}:out` | List | 탈락·이탈한 userId, 발생 순서 |
| `game:{id}:stat:{userId}` | Hash | bellSuccess, bellFail, reactionSum(ms) |
| `game:{id}:bell:{turnSeq}` | String | 최초 종 userId, SET NX EX 10. 정리 인덱스 기록까지 Lua로 처리 |
| `game:{id}:keys` | Set | 같은 게임의 모든 Redis 키, 정산 후 누락 없이 삭제하기 위한 인덱스 |
| `settled:{id}` | String | DB 반영 완료 표식, 1일 |

게임 상태 키는 첨부 명세에 따라 TTL 없이 유지하고 종료 정산 성공 후 삭제한다. 미러 전체는 Redis MULTI로 갱신한다. 원본 도메인과 보관 덱은 클라이언트가 수정할 수 없다.

최종 결과는 기존 PostgreSQL `Game`·`GameResult` 트랜잭션으로 저장한다. 중복 저장의 최종 방어는 DB의 게임 ID 유니크 제약이다. DB가 실패하면 결과를 메모리와 Redis에 남기고 1초 뒤 같은 큐에서 재시도한다. `settled: false` 동안 다음 판 시작을 거부한다. 마지막 사람이 방을 나가도 정산 재시도는 남는다. Redis 정리에 실패해도 다음 판이 그 정리 작업을 덮어쓰지 않게 한다. Redis 미러만 실패한 경우 이미 확정한 카드를 되돌리지 않고 같은 상태를 다시 저장한다.

`pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 실행한다. 실제 통합 테스트는 별도의 빈 테스트 DB를 만든 뒤 기존 마이그레이션을 적용해 실행한다. 기존 개발 DB를 초기화할 필요는 없다.

```sh
POSTGRES_DB=nlmlio_game_test pnpm db:deploy
POSTGRES_DB=nlmlio_game_test pnpm test:e2e
```

도메인 테스트는 분배·과일 합·카드 보존·벌칙·탈락·순위·타이머를 검증한다. 서비스 테스트는 가짜 시간으로 자동 내기·연결 유예·재시도·접수 순서를 검증한다. 통합 테스트는 실제 소켓·Redis·PostgreSQL을 이용해 방 시작부터 카드·동시 종·재접속·이탈·정산·Redis 정리까지 확인한다. 통합 테스트의 셔플 팩토리만 결정적인 덱으로 교체하며 게임 규칙·저장소·네트워크는 실제 구현이다.

## 인증·표시 보완 (2026-11-18)

- Web Locks 지원 브라우저는 같은 출처 탭들의 Refresh·로그인·로그아웃 쿠키 변경을 직렬화한다. Web Locks가 없는 LAN HTTP에서는 회전 충돌의 401을 최신 공용 쿠키로 두 번 재시도한다. 실패 응답은 공용 Refresh 쿠키를 지우지 않으며, 서버는 이전 토큰의 재사용을 계속 거부한다.
- 채팅 수신자의 계정 버전은 메시지당 한 번의 일괄 DB 조회로 검사한다. 각 소켓의 JWT와 현재 방 소속 검사도 유지한다.
- 닉네임 변경은 Room 도메인과 방별 큐의 Game 도메인에 전달하고 전체 상태를 방송한다. 카드·턴·승패는 바꾸지 않는다.
- 마지막 종으로 게임이 끝나도 수신 시각부터 1.8초 판정을 표시한 뒤 결과 화면으로 전환한다. 무시된 종·카드 내기의 ack는 클라이언트가 안내 문구로 표시한다.
- 게임 화면은 실제 컨테이너와 visualViewport를 측정하고, 배율이 반영된 영역을 가운데 배치한다. Enter 채팅 시작은 버튼·링크·입력 요소·모달의 키보드 동작을 가로채지 않는다.

### 네트워크 지연과 판정

WebSocket을 먼저 연결하고 실패하면 polling을 시도한다. Cloudflare 경유 자체의 전송 시간은 앱의 인증 최적화로 없어지지 않는다. 선착순은 기존 명세대로 서버 도착 순서이며, 클라이언트 시각이나 RTT 추정값으로 승자를 바꾸지 않는다. 같은 Wi-Fi에서는 Vite의 Network 주소로 직접 접속해 터널을 우회할 수 있다. 외부 직접 HTTPS 접속은 기존 `pnpm tunnel:direct`와 공유기·DNS 설정이 필요하다. 인증서·네트워크 설정을 자동 변경하지 않는다.

## 동시 키 입력 보완 (2026-11-19)

카드 내기 버튼이나 종 버튼에 포커스가 있어도 J·Space 단축키를 처리한다. 채팅 입력·모달·일반 버튼의 기본 키보드 동작은 유지한다. 같은 브라우저에서 카드 요청을 먼저 보낸 뒤 종을 누르면 `GameInputSequence`가 카드 응답을 기다리고 최신 서버 스냅샷의 `turnSeq`로 종 의도를 보낸다. 종소리와 손 애니메이션은 입력 즉시 시작한다. 종이 먼저 서버에 접수돼 판정 중이면 뒤의 카드 요청은 기존 규칙대로 차단된다. 서버 도착 순서 및 선착순 판정 규칙은 바꾸지 않는다.

오발 `game:action`의 `movedCards`는 테이블에서 보관 스택으로 옮긴 카드 수이고, `penaltyCards`는 상대에게 나눠 준 벌칙 카드 총수다. 플레이어별 덱 수량은 전체 상태 스냅샷에서 확인한다.
