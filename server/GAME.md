# 게임 서버 (FUNC-005)

서버 범위는 FUNC-005-01~13, 15~16이다(포인트 FUNC-006은 제외). 방 생성·참가·관전석·채팅에 게임 엔진을 연결했다. 클라이언트 게임 화면(`client/src/pages/game/GamePage.tsx`)이 아래 소켓 계약으로 붙어 있고, Howler 효과음(005-14)은 클라이언트가 낸다. 턴 시간(`TURN_TIME_MS`)과 게임 중 재접속 유예(`GAME_RECONNECT_GRACE_MS`)는 `shared/src/game-events.ts`에서 양쪽이 같이 쓴다.

## 규칙

- 과일 4종 × 14장 = 56장. 각 과일은 1개 카드 5장, 2개 3장, 3개 3장, 4개 2장, 5개 1장이다. 서버의 암호학적 난수로 Fisher–Yates 셔플한다.
- 방의 `PLAYER` 2~6명에게 동일 장수로 나누고 나머지는 보관 스택에 넣는다. 원래 관전자는 덱·경기 결과를 받지 않는다. 방 전체 인원은 기존 참가자 6명 + 관전석 10명 규칙을 따른다.
- 첫 차례는 참가석 입장 순서의 첫 회원이다. 탈락·이탈자는 턴에서 제외한다. 마지막 카드를 내면 종 판정까지 살아 있고 차례에서만 빠진다. 다음 종 판정 뒤에도 덱이 0장이면 탈락한다.
- 공개 테이블에서 같은 과일 합이 정확히 5이면 종 성공이다. 선착순 한 명이 테이블 전체와 보관 스택을 자기 덱 아래에 넣고 다음 라운드를 시작한다.
- **2026-11-19 수정 오발**: 오발자는 자신을 제외한 각 생존 플레이어에게 보유 카드를 1장씩 덱 아래로 준다. 탈락·이탈·관전자는 받지 않는다. 부족하면 참가석 순서로 가진 만큼만 주고, 보유 카드가 0장이면 더 주지 않는다. 모든 플레이어 앞에 쌓인 테이블 카드는 맨 위뿐 아니라 아래까지 전부 종 아래 보관 스택으로 모은다. 기존 보관 카드는 유지하며 다음 정상 종 승자가 가져간다. 오발 후 기존 차례를 이어가되 탈락한 사람은 차례에서 제외한다.
- 종 판정 결과를 `ROUND_RESULT_MS`(1.8초) 동안 표시하고, 서버도 이 동안 카드 요청을 무시한다. 스냅샷의 `roundResumeAt` 이후부터 온전한 새 차례 10초를 준다. 10초 안에 직접 내지 않으면 서버가 대신 낸다. 한 회원이 세 번 연속 자동 내기하면 이탈 처리한다. 직접 내면 연속 횟수는 0으로 돌아간다.
- 한 명만 남으면 종료한다. 최후 생존자, 탈락·이탈 순서의 역순으로 순위를 만든다. 이탈자는 패배로 기록한다. 모두 덱이 0장이면 마지막 카드 이후 10초 동안 종 기회를 주고, 응답이 없으면 마지막으로 카드를 낸 사람이 승리한다. 포인트 기능은 없다.
- 탈락·연결 유예 만료·자동 내기 이탈은 방에 관전자로 남는다. 직접 방을 나가면 소속도 제거한다. 관전자는 같은 전체 상태와 채팅을 받지만 카드 내기·종은 `SPECTATOR_FORBIDDEN`이다.
- 진행 중에도 방 코드로 관전 입장이 가능하다. 참가석이 비어 있어도 관전자로 배정하며 새 관전 입장 10석·전체 16명 제한을 지킨다. 탈락한 원래 참가자는 새 관전 정원을 소모하지 않는다. `RoomGameLifecycle.joined`가 입장자의 모든 소켓에 현재 공개 스냅샷을 보내며 덱·차례·결과에는 추가하지 않는다. 채팅·이모티콘은 가능하고 카드·종·게임 중 자리 이동은 거부한다.
- 종료 후 남아 있는 원래 참가자는 참가석으로, 원래 관전자와 도중 입장 관전자는 관전석으로 돌아간다. 게임 중 나간 방장의 권한은 종료 시 남은 첫 회원에게 넘어간다.

## 스킬 선택 (FUNC-009-01~03)

- 게임 시작 시 첫 선택을 열고 3·6·9라운드 등 세 라운드가 끝날 때마다 다음 선택을 연다. 종 판정으로 라운드가 끝나면 결과 표시(`ROUND_RESULT_MS`) 후 방 큐의 타이머가 선택을 연다. 게임이 종료되면 추가 선택은 없다.
- 후보를 받는 대상은 게임 중인 플레이어 전원(플레이어 풀)과 방의 관전자 전원(관전자 풀, 탈락·이탈해 관전 중인 사람과 도중에 들어온 관전자 포함)이다. 사람마다 후보 3칸을 서버가 뽑는다.
- 선택 중에는 `card:play`·`bell:ring`을 무시(`ignored`)하고 `turnDeadline`은 `null`이며 턴 타이머가 멈춘다. 끝나면 멈춘 시점의 남은 턴 시간부터 이어 간다.
- 마감(`skill-settle:{code}` 타이머, 열린 뒤 10초)이 지나면 못 고른 사람은 서버가 처리한다. 빈 칸이 있으면 후보 중 하나를 무작위로 넣고, 칸이 가득 찼으면 받지 않는다. 전원이 고르면 마감을 기다리지 않고 바로 끝난다.
- 탈락·이탈하면 보유 스킬이 사라진다. 방을 떠난 사람은 진행 중인 선택 대상에서도 빠진다.
- 후보와 보유 스킬은 공개 스냅샷에 넣지 않는다. 공개 스냅샷에는 `skillSuccesses`와 진행 현황 `skillPick`(마감 시각, 몇 번째, 고른 사람 수·전체)만 있고, 본인에게만 `game:skills`로 보유 스킬과 후보·내 선택을 보낸다. 상태가 바뀐 사람에게만 다시 보낸다.
- Redis 미러(`game:{id}:*`)에는 스킬 상태를 넣지 않는다(첨부 Redis 명세 유지). 프로세스 재시작 복구를 지원하지 않으므로 필요가 없다.

## 스킬 사용 (FUNC-009-04)

- `skill:use { gameId, slot, targetUserId?, expectedSkillId? }`는 보유 스킬을 사용한다. 필드 스킬의 `game:action`은 방 전체에, 개인 스킬은 시전자·대상·반사자에게만 보낸다. 지뢰 설치는 사용 이벤트를 전송하지 않는다. 바뀐 보유 슬롯은 본인의 `game:skills`로 갱신한다.
- 쓸 수 있는 스킬은 `SkillDefinition.available`이 true인 것뿐이다(현재 반짝반짝한 카드·종 옮기기·과일 6개 카드·시간 정지·침 뱉기·아마테라스·숫자 바꾸기·종 부수기·해킹·쥐새끼·러시안 룰렛·지뢰·무지개 반사·손 개 쌔게 내려치기·종 야바위·도르마무·안해). 나머지는 보유할 수 있어도 `SKILL_UNAVAILABLE`이고 칸에서 사라지지 않는다. 사용 시점은 스킬의 타이밍과 서버 상태로 검증한다.
- 플레이 중인 사람은 플레이어, 아니면 관전자로 보고 스킬의 사용 역할과 맞는지 검사한다. 대상 지정 스킬은 플레이 중인 다른 사람만 대상이 된다. 선택 중에는 조용히 무시(`ignored`)한다.
- 종 야바위: `shell {endsAt, keys, real}`을 만든다(종 4개, 키는 `BELL_SHELL_KEYS`의 1·2·3·4, 요청 번호는 0~3). 공개 스냅샷에는 `keys`·`endsAt`만 나가고 `real`은 서버만 안다. `bell:ring`에 `bell`(종 번호)을 보내야 하며, 진행 중에 `bell`이 `real`과 다르거나 없으면 5개여도 오발이고 액션에 `fake: true`가 붙는다.
- 도르마무: `ring`이 판정 직전 상태(`RewindPoint`: 덱·테이블·보관 스택·차례·종 기록·금칠/개수 증가)를 저장한다. 결과 표시 중(`resumeAt` 전)이고 판정 전후의 플레이 중인 사람이 같을 때만 쓸 수 있고(`rewindUntil`), 성공 판정을 되돌리면 성공 횟수도 1 줄이고, 되돌린 라운드의 `skillDue`를 끈다. 순번(`sequence`)과 턴 토큰을 새로 올린다.
- 안해: 플레이 중인 사람끼리 `Deck.standard().shuffle(random)`로 다시 분배하고 테이블·보관 스택·모든 효과·`SkillBook`(`reset`)·종 기록을 초기화한다. 첫 스킬 선택을 다시 열고 이전 진행은 전적에 남기지 않는다.
- 손 개 쌔게 내려치기: `ring`이 끝나면 `smashWindow {userId, endsAt: now+2000}`을 남긴다(공개 스냅샷). 클라이언트가 슬롯으로 준비하고 현재 종 키로 사용 의도를 보낸다. 창 안에서 판정을 낸 사람이 아닌 플레이어가 쓰면(`timing=ON_BELL`, 대상 없음) 그 사람을 `smashed`에 넣고 창을 닫는다. `canRing`이 `smashed`를 거부하고 다음 `ring` 판정·탈락·게임 종료에서 비운다.
- 지뢰: `mine` 플래그를 서버 내부에만 기록한다. 설치 여부와 설치 이벤트는 클라이언트로 보내지 않는다. 다음 `ring`에서 5개가 맞으면 승자 없이 테이블 카드를 모두 `pile`에 넣고 `GameAction.mined`를 보낸다. `GamePlayer.bell`·성공 횟수(`countSuccess`)는 부르지 않는다. 오발·게임 종료·성공 판정 어느 쪽이든 판정이 나면 플래그가 꺼진다.
- 무지개 반사: `useSkill`에서 단일 지정 스킬의 대상이 플레이어이고 `SkillBook.consumeSkill(target, RAINBOW_REFLECT)`가 성공하면 효과 대상을 쓴 사람으로 바꾸고 `GameAction.reflectedBy`에 원래 대상을 싣는다. 쓴 사람이 관전자면 반사하지 않는다. 직접 사용은 `timing=AUTOMATIC`이라 거부된다.
- 쥐새끼: 익명의 `rat`이 종 아래에 2초 머문다. 마감 전에 종을 부수면 `ratCrushed`와 함께 제거하고 카드는 보관 더미에 남는다. 마감에는 출발 시 보관된 장수를 시전자에게 한 번만 지급한다. 시전자는 개인 `ratResult`로 실제 결과를 받는다.
- 러시안 룰렛: 관전자가 보유 덱이 남은 플레이어를 지정한다. 대상 덱에서 최대 5장을 종 아래 보관 더미로 옮기고 `movedCards`에 실제 장수를 넣어 시전자와 대상에게 보낸다.
- 숫자 바꾸기: 내 테이블 맨 위 카드에 `Card.boost()`(과일 개수 +1)를 건다. `count`가 늘어난 값을 돌려주므로 합계·판정·공개 스냅샷(`topCard.count`, `boosted: true`)이 모두 같은 값을 쓴다. 테이블 순번과 반응 시간 기준을 갱신해 모든 참가자가 새 테이블에 종을 칠 수 있다. 걸 수 있는 카드(특수 카드·이미 늘어난 카드·6개 카드 제외)가 없으면 `SKILL_UNAVAILABLE`이고 스킬은 칸에 남는다. 카드가 `Table.remove`로 테이블을 떠나면 원복한다.
- 종 부수기: `bellBreak`(복구 시각 `endsAt`, 10~30초를 1초 단위로 서버가 무작위)로 공개한다. 화면은 복구 카운트다운을 숨긴다. 부서져 있는 동안 `canRing`은 모두 false(조용히 무시)이고 카드 내기는 그대로다. 마지막 종 기회(`current === null`)에 `timeout`이 오면 복구 시각 + `TURN_TIME_MS`로 마감을 미룬다.
- 해킹: 걸린 사람 → 새 종 키(`BELL_MOVE_KEYS` 중 무작위)를 서버가 들고 있다가 본인의 `game:skills`(`hackKey`)에만 보낸다. 공개 스냅샷에는 없다. 종 판정이나 탈락·이탈로 라운드가 넘어가면 풀린다. 키 제한은 화면이 하고 서버의 `bell:ring` 처리는 그대로다.
- 시간 정지: `timeStop`(쓴 사람·끝나는 서버 시각 `endsAt`, `TIME_STOP_MS`=3초)으로 공개한다. 정지 중 쓴 사람은 `card:play`의 차례 검사(`NOT_YOUR_TURN`)를 건너뛰고 계속 낼 수 있고(낸 뒤 차례는 그 사람 다음으로 이어진다), 쓴 사람이 아닌 사람의 `card:play`·`bell:ring`은 조용히 무시(`ignored`)한다. 턴 타이머는 멈춘 시간만큼 `deadline`을 뒤로 밀어 멈춘다(별도 타이머 없음). 정지 중인지는 요청 시각(`receivedAt`)과 `endsAt`을 비교해 정하므로 `canRing`도 시각을 받는다.
- 침 뱉기: 서버가 바꾸는 상태가 없다. 사용 알림(`game:action`의 `skill`)만 가고, 대상 본인의 클라이언트가 6초(가림 3초 + 흘러내림 3초) 연출을 보여 준다.
- 아마테라스: `burning`(걸린 사람 id 배열)으로 공개한다. 걸린 사람의 `card:play`·`bell:ring`은 무시하고, 차례를 정할 때(`nextAfter`) 건너뛴다. 걸린 사람의 차례에 쓰면 바로 다음 사람으로 넘기고 `turnId`가 바뀐다. 종 판정(성공·오발)이나 탈락·이탈로 라운드가 넘어가면 모두 풀린다. 낼 수 있는 사람이 걸린 사람뿐이라 `current`가 비면 `timeout`에서 풀고 차례를 돌려준다.
- 종 옮기기: 서버가 새 자리(0~3)와 새 키(`BELL_MOVE_KEYS` 중 하나)를 하나 정해 방 전체에 같게 쓰고 `bellMove`(자리·키·끝나는 서버 시각 `endsAt`, 연출 0.5초 + 3초 = `BELL_MOVE_MS`)로 공개한다. 판정과 `bell:ring` 처리는 평소와 같고, Space 대신 새 키만 쓰는 것과 이동 중 처음 300ms 입력 무시는 화면이 한다. 끝났는지는 클라이언트가 서버 시각과 `endsAt`으로 판단한다(타이머 없음). 다시 쓰면 새로 정하고, 게임이 끝나면 사라진다.
- 과일 6개 카드: 사용자별 예약으로 두고 그 사람이 다음에 내는 카드를 같은 과일의 6개짜리 특수 카드(`Card.six`)로 바꾼다. 원래 카드는 함께 사라진다. 합계는 맨 위 카드 기준이라 6으로 세고, 판정이 나면(성공·오발 모두) 테이블 어디에 있든 사라져 승자도 보관 스택도 가져가지 않는다. 공개 스냅샷의 `topCard`는 `count: 6, special: true`다.
- 반짝반짝한 카드는 사용자별 예약으로 두고, 그 사람이 다음에 내는 카드에 `Card.gild()`를 건다. 공개 스냅샷의 `topCard.gilded`로 보이고, 카드가 테이블을 떠나면(`Table.remove`) 사라진다.

## 계층과 동시성

`GameGateway → GameService → Game / GamePlayer / Table / Deck` 순으로 연결된다. 도메인에는 NestJS·DB·Redis·Socket.io 의존성이 없고, 모든 규칙 변경이 동기로 끝난다. 서비스는 `RoomQueue`에 요청을 접수한 다음 인증·Redis·DB를 기다린다. 먼저 접수된 종 요청이 느린 인증 때문에 뒤 요청에 추월당하지 않는다. 자동 턴, 연결 유예 만료, 게임 중 나가기와 실제 방 소속 제거도 같은 큐에서 처리한다.

게임 원본은 서버 1대의 메모리 객체이고 Redis에는 내부 상태를 미러링한다. 자동 턴은 서버의 절대 마감 시각을 사용한다. 다른 탭이 연결돼 있으면 끊김으로 세지 않는다. 마지막 탭이 끊겼을 때 활성 플레이어는 게임 중 5초 이탈 유예를 적용한다. 관전자(도중 입장·탈락 포함)는 게임 진행 여부와 무관하게 60초 안에 돌아오면 유지하고, 지나면 방에서 정리한다. 연결이 없는 채 HTTP로 관전 입장한 경우에도 같은 정리 타이머를 건다. 재접속 시 같은 게임의 전체 공개 스냅샷을 보낸다. 게임 중 턴 타이머는 연결 유예 중에도 계속 진행한다.

현재 방 저장소도 메모리이므로 **프로세스 재시작 후 게임·방의 자동 복구는 지원하지 않는다**. Redis 미러를 새 서버의 권위 있는 상태로 읽어 복원하지 않으며, 여러 게임 서버 운영을 지원하는 분산 엔진도 아니다.

## 소켓 계약

기존 같은 출처 Socket.io 연결에서 `auth.token`에 Access JWT를 넣는다. 방·게임·채팅 이벤트는 매 요청에도 현재 소켓 토큰·계정 버전을 검증한다. 클라이언트는 만료 30초 전에 Refresh를 회전하고 `auth:refresh`로 기존 연결의 인증 정보만 교체한다. 토큰이 만료된 채 메시지를 받으려 하면 서버는 전달을 막고 `auth:required`를 보낸다. 클라이언트는 인증 갱신 후 채팅 채널을 재확인한다. 새 토큰의 회원 ID가 원래 소켓과 다르면 교체를 거부한다. 발신자 ID·카드·클라이언트 시각은 입력으로 받지 않는다.

| 방향 | 이벤트 | 페이로드 |
|---|---|---|
| C→S | `auth:refresh` | `{ token }` — 동일 회원의 유효한 Access 토큰으로 기존 연결 갱신 |
| S→C | `auth:required` | `{ code: TOKEN_EXPIRED }` — 채팅 수신 인증 갱신 요청 |
| C→S | `room:start` | `{}` — 방장만, 참가자 최소 2명 |
| C→S | `card:play` | `{ gameId, turnId }` |
| C→S | `bell:ring` | `{ gameId, turnSeq }` |
| C→S | `skill:pick` | `{ gameId, choice }` — `choice`는 `{ slot, replace? }`(후보 칸, 보유 칸이 가득 찼으면 바꿀 칸) 또는 `{ decline: true }`(가득 찼을 때만). 열린 선택이 없거나 늦었거나 이미 골랐으면 `ignored` |
| C→S | `skill:use` | `{ gameId, slot, targetUserId?, expectedSkillId? }` — 보유 스킬 사용. 대상 지정 스킬만 `targetUserId`를 보낸다. 선택 중이면 `ignored` |
| C→S | `game:sync` | `{}` — 이 소켓에 현재 전체 상태 재전송(스킬 상태 포함) |
| C→S | `game:return` | `{}` — 종료·정산 확인 후 이 소켓에 `game:state: null` |
| S→C | `game:state` | `GameStateEvent \| null` — 스냅샷 + 보낸 순간의 서버 시각 `serverTime`(클라이언트 시계 차이 계산용) |
| S→C | `game:skills` | `SkillStateEvent \| null` — **본인에게만**. 보유 스킬과 선택 후보·내 선택 |
| S→C | `game:action` | 카드 내기·종 판정·이탈·연결 변경 `GameActionEvent` (gameId·revision 포함) |

Ack는 `{ ok: true }`, 지난 중복 요청이면 `{ ok: true, ignored: true }`, 실패면 `{ ok: false, code }`다. 연결 끊김으로 Ack가 오지 않으면 클라이언트는 시간 초과로 안내하고 `game:sync` 또는 재접속 후 상태를 확인해야 한다.

스냅샷의 `turnId`는 새 차례(카드 내기·종 판정)에 변경된다. 카드 내기에는 마지막 스냅샷의 `turnId`를 그대로 보낸다. `turnSeq`는 카드가 공개될 때마다 증가한다. 종에는 현재 `turnSeq`를 보낸다. 같은 `turnSeq`의 종은 판정이 한 번 끝나면 다음 카드가 나오기 전까지 무시한다. `gameId`는 이전 판의 지연 요청이 새 판에 영향을 주지 않도록 반드시 함께 보낸다.

스냅샷에는 보유 카드 **개수**, 맨 위 공개 카드, 테이블 개수, 과일 합계, 상태, 연결 상태, 자동 내기 횟수, 턴·마감 시각·판정 후 재개 시각(`roundResumeAt`)과 최종 결과가 있다. 숨긴 손패의 과일·순서는 보내지 않는다. `revision`은 공개 상태 변경 순서이며 클라이언트가 오래된 상태를 걸러낼 수 있다. `settled`는 결과 DB 반영 완료 여부다.

## Redis 미러와 정산

| Key | 형식 | 내용 / 수명 |
|---|---|---|
| `game:{id}` | Hash | roomCode, status, round, turnUserId, turnSeq, turnId, lastPlayAt, roundResumeAt, startedAt |
| `game:{id}:order` | List | 살아 있는 참가자 userId, 자리 순서 |
| `game:{id}:hand:{userId}` | List | 숨긴 덱, 왼쪽이 맨 위. `S3` 같은 과일 이니셜+개수 |
| `game:{id}:table:{userId}` | List | 테이블 전체 카드, 왼쪽이 맨 위 |
| `game:{id}:pile` | List | 종 아래 보관 카드 |
| `game:{id}:out` | List | 탈락·이탈한 userId, 발생 순서 |
| `game:{id}:stat:{userId}` | Hash | bellSuccess, bellFail, reactionSum(ms) |
| `game:{id}:bell:{turnSeq}` | String | 최초 종 userId, SET NX EX 10. 정리 인덱스 기록까지 Lua로 처리 |
| `game:{id}:keys` | Set | 같은 게임의 모든 Redis 키, 정산 후 누락 없이 삭제하기 위한 인덱스 |
| `settled:{id}` | String | DB 반영 완료 표식, 1일 |

게임 상태 키는 첨부 명세에 따라 TTL 없이 유지하고 종료 정산 성공 후 삭제한다. 미러 전체는 Redis MULTI로 갱신한다. 원본 도메인과 보관 덱은 클라이언트가 수정할 수 없다.

최종 결과는 기존 PostgreSQL `Game`·`GameResult` 트랜잭션으로 저장한다. 중복 저장의 최종 방어는 DB의 게임 ID 유니크 제약이다. DB가 실패하면 결과를 메모리와 Redis에 남기고 1초 뒤 같은 큐에서 재시도한다. `settled: false` 동안 다음 판 시작을 거부한다. 마지막 사람이 방을 나가도 정산 재시도는 남는다. Redis 정리에 실패해도 다음 판이 그 정리 작업을 덮어쓰지 않게 한다. Redis 미러만 실패한 경우 이미 확정한 카드를 되돌리지 않고 같은 상태를 다시 저장한다.

## 인증·표시 보완 (2026-11-18)

- Web Locks 지원 브라우저는 같은 출처 탭들의 Refresh·로그인·로그아웃 쿠키 변경을 직렬화한다. Web Locks가 없는 LAN HTTP에서는 회전 충돌의 401을 최신 공용 쿠키로 두 번 재시도한다. 실패 응답은 공용 Refresh 쿠키를 지우지 않으며, 서버는 이전 토큰의 재사용을 계속 거부한다.
- 채팅 수신자의 계정 버전은 메시지당 한 번의 일괄 DB 조회로 검사한다. 각 소켓의 JWT와 현재 방 소속 검사도 유지한다.
- 닉네임 변경은 Room 도메인과 방별 큐의 Game 도메인에 전달하고 전체 상태를 방송한다. 카드·턴·승패는 바꾸지 않는다.
- 마지막 종으로 게임이 끝나도 수신 시각부터 1.8초 판정을 표시한 뒤 결과 화면으로 전환한다. 무시된 종·카드 내기의 ack는 클라이언트가 안내 문구로 표시한다.
- 게임 화면은 실제 컨테이너와 visualViewport를 측정하고, 배율이 반영된 영역을 가운데 배치한다. Enter 채팅 시작은 버튼·링크·입력 요소·모달의 키보드 동작을 가로채지 않는다.

### 네트워크 지연과 판정

WebSocket을 먼저 연결하고 실패하면 polling을 시도한다. Cloudflare 경유 자체의 전송 시간은 앱의 인증 최적화로 없어지지 않는다. 선착순은 기존 명세대로 서버 도착 순서이며, 클라이언트 시각이나 RTT 추정값으로 승자를 바꾸지 않는다. 같은 Wi-Fi에서는 Vite의 Network 주소로 직접 접속해 터널을 우회할 수 있다. 외부 직접 HTTPS 접속은 기존 `pnpm tunnel:direct`와 공유기·DNS 설정이 필요하다. 인증서·네트워크 설정을 자동 변경하지 않는다.

## 동시 키 입력 보완 (2026-11-19)

카드 내기 버튼이나 종 버튼에 포커스가 있어도 J·Space 단축키를 처리한다. 채팅 입력·모달·일반 버튼의 기본 키보드 동작은 유지한다. 같은 브라우저에서 카드 요청을 먼저 보낸 뒤 종을 누르면 `GameInputSequence`가 카드 응답을 기다리고 최신 서버 스냅샷의 `turnSeq`로 종 의도를 보낸다. 종소리는 입력 즉시 시작하며, 손 애니메이션은 서버의 `bellHands` 스냅샷을 받은 뒤에만 시작한다. 종이 먼저 서버에 접수돼 판정 중이면 뒤의 카드 요청은 기존 규칙대로 차단된다. 서버 도착 순서 및 선착순 판정 규칙은 바꾸지 않는다.

오발 `game:action`의 `movedCards`는 테이블에서 보관 스택으로 옮긴 카드 수이고, `penaltyCards`는 상대에게 나눠 준 벌칙 카드 총수다. 플레이어별 덱 수량은 전체 상태 스냅샷에서 확인한다.

## 서버 판정 후 손 표시 (2026-11-19)

`domain/game/bell-hands.ts`가 첫 판정 직전의 생존 참가자와 손 접수 순서를 관리한다. 최초 판정 후 `BELL_HAND_WINDOW_MS`(200ms) 안에 Gateway에 도착한 같은 테이블의 요청만 손 목록에 추가한다. 인증·DB 처리 대기 시간이 길어도 Gateway의 원래 접수 시각으로 구간을 검사한다. 참가자가 아닌 사람, 다른 테이블, 중복 사용자, 201ms 이후의 요청은 추가하지 않는다. 최후 종으로 탈락한 사람도 판정 직전 참가자였다면 이 구간의 손 표시만 추가할 수 있다.

`game:state.bellHands`에는 `turnSeq`, 서버 마감 `windowClosesAt`, 판정 종료 `displayUntil`, 판정 직전 참가자 `eligibleUserIds`, 서버 접수 순서 `userIds`가 포함된다. 첫 손은 카드 판정이 끝난 뒤에만 방송한다. 추가 손도 같은 방 큐에서 인증 후 반영하고 revision을 올려 모든 플레이어와 관전자에게 같은 순서를 보낸다. 추가 손은 승패·카드 이동·벌칙·통계를 다시 바꾸지 않는다. 새 카드를 공개하면 이전 손 목록을 비운다.

클라이언트는 클릭·키 입력으로 손 목록을 만들지 않는다. 서버 목록을 받은 손만 140ms 동안 중앙으로 이동시키고, 먼저 도착한 손부터 아래에 쌓아 판정 결과가 끝날 때까지 유지한다. 번호 없이 접수 순서대로 이름을 표시하며 모션을 줄인 환경에서도 마지막 위치를 유지한다. 종소리만 입력 즉시 재생한다. 손이 이미 서버 목록에 포함된 무시된 종 ack는 `handAccepted: true`를 추가해 불필요한 실패 안내를 띄우지 않는다. 서버 도착 순서 판정은 그대로이며 네트워크 전송 지연 자체를 보정하지 않는다.
